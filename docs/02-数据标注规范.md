# 02 · 数据标注规范

> 这份文档的作用：**让不同人标出来的数据是同一个标准**。
> 标注规范不写清楚，模型效果差的时候你分不清是"模型不行"还是"标签本身在打架"。

---

## 1. 类别定义（6 类）

标注时先问：**这个问题最终由哪个班组上门解决？**

| 编号 | 类别 | 典型问题 | 高频词 | 明确不属于 |
|---|---|---|---|---|
| `plumbing` | **水电维修** | 漏水、跳闸、没电、水压小、下水堵、灯不亮、插座坏、马桶堵 | 漏水、滴水、跳闸、停电、插座、水龙头、下水道、马桶、灯 | 空调不制冷（→ hvac）、网线插口坏（→ network） |
| `carpentry` | **家具门窗** | 门锁坏、门关不上、窗户漏风、桌椅腿断、床板塌、柜门掉、纱窗破 | 门锁、合页、窗户、床板、桌腿、柜门、纱窗、钥匙 | 玻璃碎了（→ plumbing 或 other，看是否涉及安全） |
| `network` | **网络与设备** | 校园网连不上、WiFi 掉线、投影仪不亮、电脑开不了机、打印机卡纸、门禁刷不开 | 网线、WiFi、断网、投影、打印、门禁、监控、路由器 | 手机连不上 WiFi（个人设备，→ other） |
| `cleaning` | **保洁环境** | 垃圾没倒、走廊有异味、地面积水、蚊虫、公共区域脏、下水道反味 | 垃圾、异味、积水、蚊虫、打扫、消毒、脏、臭味 | 水管漏水导致的积水（→ plumbing） |
| `hvac` | **空调通风** | 空调不制冷/不制热、出风口异响、暖气不热、风扇坏、新风系统 | 空调、暖气、风口、制冷、制热、扇 | 电风扇插电不转（→ plumbing，是电路问题） |
| `other` | **其他/咨询** | 投诉、咨询政策、非维修类、无法判断 | 投诉、咨询、建议、问一下、什么时候 | 所有能归到上面 5 类的，都不要放这里 |

### 判定优先级（一条工单涉及多个类别时）

按这个顺序取**第一个命中**的：

```
1. 有安全隐患的（漏电、冒烟、漏水到楼下、门锁不上） → 按"源问题"归类
   例：「水管漏水把插座泡了」→ plumbing（源问题是水管）
2. 多个问题并列时，取"用户最想解决的"那个
   例：「灯不亮，顺便空调也不冷」→ plumbing（主诉在前）
3. 描述太短无法判断（< 6 个字且无上下文） → other
   例：「坏了」「不行」「麻烦看下」
```

## 2. 紧急度定义（3 档）

**判定顺序：从 P0 往下问，命中即停。**

### P0 · 紧急（2 小时内必须响应）

满足**任意一条**：

- 人身安全隐患：漏电、冒烟、明火、燃气味、玻璃破碎、门锁坏了关不上
- 影响范围大：整层/整栋停水停电、主管道爆管、消防设施异常
- 财产持续损失：漏水已淹没地面/渗到楼下、水管持续喷水
- 特殊人群被困：有人被反锁在房间/电梯

### P1 · 较急（24 小时内响应）

满足**任意一条**且不满足 P0：

- 基本生活功能丧失：没热水、马桶堵塞无法使用、网络完全断、空调完全不工作（极端天气）
- 影响正常教学/办公：教室投影坏了、办公室门锁坏、实验室设备断电
- 有扩大风险：小量漏水未处理、电线发热

### P2 · 一般（72 小时内响应）

其余全部：

- 不影响基本生活：灯闪烁、柜门松动、纱窗破小洞、水龙头轻微滴水
- 咨询/投诉类
- 无法判断的

### 紧急度标注的常见分歧

| 说法 | 正确判法 | 理由 |
|---|---|---|
| 「空调不制冷」 | P1（夏天）/ P2（春秋） | 看季节，标注时按采集时间判断 |
| 「马桶堵了」 | P1 | 唯一卫生间不能用 = 基本功能丧失 |
| 「灯坏了」 | P2 | 有自然光或其他光源 |
| 「漏水但是滴」 | P2 | 未造成积水/渗漏 |
| 「门锁坏了，人在里面」 | P0 | 被困 |

## 4. 数据格式

统一存 `CSV`（UTF-8 无 BOM），字段见 [../data/schema.md](../data/schema.md)。

一行 = 一条工单：

```csv
id,text,location,category,urgency,collected_at,source,note
t0001,3号楼502卫生间水管接口漏水 地上已经积了一层,3号楼502,plumbing,P0,2026-11-01,export,
```

**规则**：
- `text` 保留用户原话，**不要改写错别字、不要删口语**——模型要适应真实输入
- `location` 有就填，没有留空（不要编）
- `note` 写"为什么这么标"，只在有争议时填
- 一条工单如果无法判断类别，标 `other` 并在 `note` 写"信息不足"

## 5. 采集与合规

### 可以采的

- 学校报修系统导出的历史工单（**必须脱敏**：删姓名、电话、精确门牌）
- 校园论坛/贴吧/表白墙中的公开求助帖（只取文本，不取用户信息）
- 自己按真实语气**模拟撰写**（在报告里必须写明"模拟数据"占比）

### 绝对不要

- 真实的姓名、手机号、身份证号、精确房间号（改为"3号楼5层"这种粒度）
- 带情绪的真人对话截图原文（可能涉及隐私）
- 任何需要登录才能看到的内容

### 脱敏处理

```python
# 建议在入库前统一过一遍
import re
text = re.sub(r"1[3-9]\d{9}", "<PHONE>", text)          # 手机号
text = re.sub(r"\d{3,4}[-#]?\d{3,4}", "<ROOM>", text)    # 房间号（视情况）
```

## 6. 标注流程

```
1. 抽 50 条做预标注（两人独立标，算 Kappa）
        ↓ Kappa < 0.75 → 回来改规范，不要继续标
2. 大规模标注（一人主标，每 100 条抽 10 条复核）
        ↓
3. 分歧讨论 → 有争议的写进本文档"边界案例"表
        ↓
4. 冻结规范（之后不再改，除非发现根本性错误）
        ↓
5. 切分训练/验证/测试（分层采样，保证每类比例一致）
```

**Kappa 的意义**：0.6 以下说明规范有歧义，标得再多也是噪声。

---

## 7. 一句话总结

**标注规范的价值不在于"权威"，而在于"一致"。**
宁可用一个不完美但所有人一致执行的标准，也不要用一个完美但各自理解的标准。
